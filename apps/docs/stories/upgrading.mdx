# Upgrading to 1.0

This page lists what changed for someone who comes from the 0.x versions of `plume-ui-react`. From 1.0 on, the
public API follows semver: a breaking change only arrives in a major version, and this page will list it.

## One prop for the classes of the parts

A component that has inner parts takes a single `classNames` prop, a record keyed by part. The loose props that
existed in 0.x are gone. `classNames` adds its class in every variant, next to the Plume classes, and with
`variant="unstyled"` it is the only class a part has.

```tsx
// Before
<Checkbox inputClassName='h-4 w-4' labelClassName='font-semibold'>Accept</Checkbox>

// After
<Checkbox classNames={{ input: 'h-4 w-4', label: 'font-semibold' }}>Accept</Checkbox>
```

Every component exports its `<Name>Part` type, for example `CheckboxPart`, with the keys it accepts.

## The look of the `DatePicker` goes on the `DatePicker`

`variant`, `size` and `shape` style the input and the calendar together, so they go on the `DatePicker` and no
longer on the `DatePickerInput`.

```tsx
// Before
<DatePicker onChange={onChange}>
  <DatePickerInput variant='filled' size='sm' />
  <DatePickerCalendar />
</DatePicker>

// After
<DatePicker onChange={onChange} variant='filled' size='sm'>
  <DatePickerInput />
  <DatePickerCalendar />
</DatePicker>
```

## `className` goes to the outermost element

`className` and `style` always land on the outermost element a component renders, and `classNames.input` reaches the
native control. It changes for the components that wrap their `<input>` or `<textarea>`:

<table>
  <thead>
    <tr><th>Component</th><th>Before</th><th>After</th></tr>
  </thead>
  <tbody>
    <tr><td><code>Input</code> with addons, elements or <code>revealable</code></td><td><code>className</code> on the <code>&lt;input&gt;</code></td><td><code>className</code> on the group, <code>classNames.input</code> on the <code>&lt;input&gt;</code></td></tr>
    <tr><td><code>Textarea</code> with <code>showCount</code></td><td><code>className</code> on the <code>&lt;textarea&gt;</code></td><td><code>className</code> on the wrapper, <code>classNames.input</code> on the <code>&lt;textarea&gt;</code></td></tr>
    <tr><td><code>DatePicker</code>, <code>TimePicker</code></td><td><code>className</code> on the <code>&lt;input&gt;</code></td><td><code>className</code> on the root, <code>classNames.input</code> on the <code>&lt;input&gt;</code></td></tr>
    <tr><td><code>DatePickerInput</code>, <code>TimePickerInput</code></td><td><code>className</code> on the <code>&lt;input&gt;</code></td><td><code>className</code> on the field with its button, <code>classNames.input</code> on the <code>&lt;input&gt;</code></td></tr>
  </tbody>
</table>

```tsx
// Before
<DatePicker onChange={onChange} variant='unstyled' className='form-control' />

// After
<DatePicker onChange={onChange} variant='unstyled' classNames={{ input: 'form-control' }} />
```

An `Input` or a `Textarea` with nothing around it keeps `className` on the native element, because it is the
outermost one.

## `useClickOutside` is removed

The overlays of the library close with their own handling of Escape and of a press outside. If you used the hook for
something else, a `pointerdown` listener does the same:

```tsx
useEffect(() => {
  const close = (event: PointerEvent): void => {
    if (ref.current && !ref.current.contains(event.target as Node)) onClose()
  }
  document.addEventListener('pointerdown', close)
  return () => document.removeEventListener('pointerdown', close)
}, [onClose])
```
