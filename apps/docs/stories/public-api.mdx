# Public API

From 1.0 on, `plume-ui-react` follows semver: a breaking change only arrives in a major version. This page says what
that covers, so you know what you can build on and what can change in any release.

## What is not

- The class names of the CSS. They have a hash (`_button_q0nr6_3`) that changes with the CSS. Style with
  `className`, the `data-plume-*` attributes or the tokens.
- The component variables that no page documents, and the structure of the HTML a component renders beyond its parts
  and their order.
- The files inside `dist`. Import only from the paths of the table above.
- The look of the default theme, to a point: its colors, sizes and shadows can be adjusted in a minor release, for
  accessibility or to fix a defect, and the change is in the [changelog](https://github.com/darioegb/plume-ui-react/blob/main/packages/plume-ui-react/CHANGELOG.md). A token is never removed or renamed in a minor.

## What is a breaking change

- Removing or renaming an export, a prop, a part, a token, a `data-plume-*` attribute or a documented variable.
- Changing the type of a prop in a way that makes code that compiled stop compiling.
- Changing the default of a prop, or the element a part renders.
- Moving a breakpoint of the scale (`sm` 40rem, `md` 48rem, `lg` 64rem, `xl` 80rem, `2xl` 96rem).

These are not: a new prop, part, token or variant, a new default theme value that keeps the contrast, a fix for a
behavior that did not match its documentation, and a change in anything of the previous list.

Something deprecated stays at least one major version, with a note in the API reference and in the changelog.
