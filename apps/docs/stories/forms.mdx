# Forms

Plume does not depend on any form library. Its controls follow two rules, so they work with react-hook-form,
Formik, TanStack Form or plain state:

- A control that is a single native element (`Input`, `Textarea`, `Checkbox`, `Toggle`, `Radio`) takes `name`, `onChange`,
  `onBlur` and `ref` like the element does.
- Every other control reports its value with `onValueChange(value)` and takes it back with `value`.

The examples use <a href='https://react-hook-form.com/' target='_blank' rel='noopener noreferrer'>react-hook-form</a>, which is not a dependency of the library.

## Native controls: `register`

```tsx
const { register, handleSubmit, formState: { errors } } = useForm<Values>()

<form noValidate onSubmit={handleSubmit(onSubmit)}>
  <Field errorText={errors.email?.message} label='Email' required>
    <Input type='email' {...register('email', { required: 'Enter your email.' })} />
  </Field>
  <Field label='Notify me' orientation='inline'>
    <Toggle {...register('notify')} />
  </Field>
</form>
```

`register` hands the `ref` to the `<input>`, so a failed rule focuses it. The `ref` of `Input`, `Textarea`, `Checkbox`,
`Toggle` and `Radio` is always the native element, with or without parts.

## The other controls: `Controller`

```tsx
const { control, handleSubmit } = useForm<Values>({ defaultValues: { room: '', volume: 40 } })

<Controller
  control={control}
  name='room'
  render={({ field, fieldState }) => (
    <Field errorText={fieldState.error?.message} label='Room' required>
      <Select name={field.name} onValueChange={field.onChange} value={field.value}>
        <SelectTrigger placeholder='Pick a room' ref={field.ref} />
        <SelectContent>
          <SelectOption value='single'>Single</SelectOption>
          <SelectOption value='double'>Double</SelectOption>
        </SelectContent>
      </Select>
    </Field>
  )}
  rules={{ required: 'Pick a room.' }}
/>

<Controller
  control={control}
  name='volume'
  render={({ field }) => (
    <Field label='Volume'>
      <Slider name={field.name} onValueChange={field.onChange} value={field.value} />
    </Field>
  )}
/>
```

Where the `ref` goes, so the form can focus the control when a rule fails:

- `Select`: `ref` on its `SelectTrigger`.
- `NumberInput`: `ref` on the root, which is the native input.
- `DatePicker` and `TimePicker`: `ref` on the root, which is the native input.

`reset()` puts every control above back to its default value, because each one is controlled through `value`.

## Errors

Pass the message to the `errorText` of a `Field`. It marks the control as invalid and links the message with
`aria-describedby`, so a screen reader reads it with the control.

Without a `Field`, give the control `aria-invalid` and `aria-describedby` and render the message yourself.
