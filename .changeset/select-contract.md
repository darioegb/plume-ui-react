Select follows the parts contract. **Breaking:** `SelectTrigger` sends its `ref`, `className` and `style` to the same element, its outer `div` (`data-plume-select-trigger`), instead of forwarding the `ref` to the combobox button, so the `ref` is now an `HTMLDivElement`; put the `ref` of a form library on `SelectCombobox` (`<SelectTrigger><SelectField><SelectCombobox ref={field.ref} /></SelectField><SelectChevron /><SelectHidden /></SelectTrigger>`) to keep focusing the control on an error. `SelectTrigger` also takes `title`. **Breaking for CSS that targets the parts:** `data-plume-select-control` is now `data-plume-select-trigger` and `data-plume-select-panel` is `data-plume-select-content`. `SelectClear` is built on `OverlayClose`, so it takes `label` (it defaults to `labels.clear`) and an element as `children` becomes the button, and its `ref` is an `HTMLElement`. The `+N` chip of `SelectChips` reads the new `labels.overflow(hidden)` (default `+N`), a key of `SelectLabels` that translations of the `select` messages can set. The visually hidden list of the chosen options inside the combobox of a chips select is now an exported part, `SelectChipsSummary` (`data-plume-select-chips-summary`). `SelectOwnProps` is exported.
